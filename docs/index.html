Myxo 1.5

The language whose runtime is a living law. seed, reinforce, decay, agent aren't library calls — they're the semantics. Functions are agents; variables are pathways that strengthen each time they're read; the mesh gardens itself.

Myxo is a small, embeddable language built from scratch in plain Node — zero dependencies — with its own parser, interpreter, stdlib, tests, formatter, REPL, language server, and CLI. Its only bridge to the world is a capability fence: an Myxo script can touch nothing the host didn't hand it.

The law, executing

The reinforce/decay law isn't a metaphor bolted on top — it runs the runtime, across both memory and parallel execution:

agent hot(x) { report x * x }         # a hot, pure agent auto-memoizes — used paths reinforce
decay cold                            # quiet pathways fade; prune sweeps the weak

schedule("pool", [fast, slow], work)  # a batch flows across worker threads, by each tube's speed
flows("pool")    ->    { fast: 7.1, slow: 1.04 }   # the pool LEARNED which worker is faster

Nothing else makes one law govern what is remembered and how work is scheduled. The language is the architecture.

Why Myxo

  • Capability by construction — not a sandbox bolted on; absence. spend() doesn't exist in an agent's universe unless granted, so there's nothing to bypass.
  • Code that reads like intent — seed, reinforce, when, match, attempt/rescue — a vocabulary a human audits at a glance and a model emits cleanly.
  • The program gardens itself — hot pure agents memoize automatically; cold pathways can be metabolized. The law, executing.

Run it

node myxo.js lsp                            # stdio language server
